# Первый диагностический прогон (2026-10-08)

Это проверка исследовательского пайплайна. Новый native-кандидат не улучшил
обнаружение и не принят в production.

## Воспроизведение

```sh
make bootstrap prepare train
uv run --locked saifety-lab bootstrap --onnx
uv run --locked saifety-lab compare-native --deberta
```

Для DeBERTa нужны заранее загруженные локальные ONNX-модель, tokenizer и runtime,
указанные в README. Датасеты закреплены в `sources.lock.json`; веса и подробные
отчёты появляются в игнорируемом `artifacts/`.

## Результат

У всех классификаторов одинаковые 387 validation и 1046 test примеров после
двух общих исключений по token window. В test — 90 атак и 956 benign примеров.
Каждый порог выбран только на validation при бюджете FPR 1%.

| Классификатор | Порог | Validation FPR | Test найдено атак | Test FP | Test FPR |
| --- | --- | --- | --- | --- | --- |
| Python native candidate → Go | 0.9842852329400773 | 0.568% | 0/90 | 11/956 | 1.151% |
| Shipped native, перекалиброванный | 0.959502385071211 | 0.852% | 1/90 | 18/956 | 1.883% |
| DeBERTa | >1 (`no_alerts`) | 0% | 0/90 | 0/956 | 0% |

Для DeBERTa при этом бюджете не найден полезный operating point: порог отключает
все сигналы. Нулевая FPR здесь не означает хорошую защиту. На test FPR может
превысить validation budget; подробный отчёт содержит counts и 95% Wilson intervals.
Результат shipped нельзя сравнивать напрямую с прежним результатом при пороге 0.8.
Это оценка классификаторов без правил и политики сканера.

Python/Go native prediction delta: `8.881784197001252e-16`. Tiny transformer
прошёл настоящее обучение, ONNX-экспорт и сравнение Python ONNX Runtime с Go
при допуске `1e-6`; этот smoke не является оценкой качества трансформера.

## Ограничения и следующий этап

Все 90 атак test — English; другие языки представлены только benign примерами.
BIPIA labels не содержат полный контекст разрешённой задачи и источника.
Эти числа не измеряют успех атаки на реального агента или мультиязычное покрытие.
Десять известных пропусков сканера остаются development/regression корпусом.

Для целевой модели нужен контекстный корпус по типам атак и языкам из lab #3,
затем обучение и оценка полноценного кандидата. Автоопределение языка, mixed-language
routing и контекстный вход ещё не реализованы; перевод остаётся экспериментальным.
Production-веса и пороги приложения этим прогоном не меняются.
