# Границы Python-лаборатории

`lab-py` принимает закреплённые данные lab и локальные checkpoints, обучает
кандидатов и формирует артефакты. Production-приложение не зависит от Python.

Путь кандидата: данные lab → обучение в lab-py → артефакт с manifest → Python/Go
parity → независимая оценка → PR в prompt-injection-model → явное обновление
закреплённой модели приложения. Ни одна команда не публикует веса автоматически.

В manifest должны сохраняться источник модели, хеши данных и токенизатора,
схема входа/выхода, индекс attack, окно, параметры обучения и данные проверки
совместимости. При изменении схемы приложение должно явно поддержать её.

Следующие этапы целевой архитектуры:

1. Seed-корпус по 7 типам и EN/RU/ES/ZH добавлен в lab #6; независимая проверка
   человеком, естественные документы и расширение остаются в lab #3.
2. Исследовательский context-json-v1 и native ablations готовы; runtime adapter
   и контекстный multilingual encoder ещё нужны. Контракт содержит задачу
   пользователя и provenance отдельно от
   недоверенного текста. Данные не могут сами повышать свой trust.
3. Определение языка по фрагментам, mixed/unknown language, эксперимент перевода
   против многоязычного detector. Повелительное наклонение — дополнительный
   признак; никакой фильтр не должен исключать оригинал из проверки.
4. Полное покрытие структурированного MCP, длинных/декодированных фрагментов и
   явный incomplete status. Политика приложения выбирает действие по результатам
   правил, модели и полноте анализа.
5. Проверка успеха защиты и выполнения легитимной задачи в стенде агента.

Текущие команды включают raw-text workflow и контекстные native ablations. Они не
заявляют покрытие всех языков или исправление существующих пропусков сканера.
