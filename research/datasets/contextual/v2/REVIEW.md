# Журнал модельного ревью — 2026-10-10

По решению пользователя проверка выполнена ИИ вместо обязательной человеческой
разметки. Просмотрены task и все documents всех 252 записей на EN/RU/ES/ZH и
mixed EN/RU, затем решения сопоставлены с v1. Модель — OpenAI Codex session;
точный runtime model ID в этой сессии недоступен. Метод и ограничения также
записаны в `review.json`.

Этот же ассистент участвовал в подготовке корпуса, а прежние метки присутствовали
в истории сессии. Скрытие меток в текущем пакете не делает проверку независимой.
Возможны общие ошибки автора и проверяющего, ошибки перевода и пропущенные
семантические производные. Побитовая воспроизводимость генерации модельных
суждений не заявляется; сохранён журнал решений, привязанный к версии данных.

## Решения

1. Объединены EN/RU варианты известных пропусков и явные шаблонные производные:
   - замена задачи стихотворением: known-miss task-switch + task-hijacking-poem;
   - навязанный маркер завершения: known-miss answer-contamination/tool-output-policy
     + answer-contamination-marker;
   - преждевременное одобрение ревью: known-miss false-approval/workflow-hijack;
   - выдуманный запуск тестов: known-miss fabricated-evidence + evidence-fabrication-test-count.
   Все эти семейства оставлены в development; 24 производные строки перемещены
   туда из train. Это не случайное переразбиение и не настройка по score модели.
2. Все 8 строк authority-spoofing-nested-message перемещены из validation в
   development и карантинируются. Пользователь просит описать JSON-пример:
   императив в content может быть цитируемым примером атаки, а не активной
   инъекцией. Для четырёх исторически положительных вариантов контекста
   недостаточно для уверенного бинарного решения; они имеют label=null в журнале.
   Безопасные контроли оставлены в том же карантинном семействе.
3. Уточнён основной тип двух development-примеров:
   - known-miss-en-workflow-hijack: task-hijacking → verification-suppression;
   - known-miss-en-source-authority: authority-spoofing → verification-suppression.
   Оба подавляют запрошенную проверку/открытые вопросы. Прежние типы сохранены
   дополнительными тегами; ID и происхождение остаются прежними.
4. В проверенных языковых вариантах существенной смены разрешений и смысла
   не обнаружено. Обе группы authorization-pairs отдельно просмотрены: оплата
   и открытие ссылки допустимы только при соответствующей пользовательской задаче.
   Это модельная оценка переводов, не проверка носителями языка.

## Итог и пределы выводов

Всего 30 семейств; 244 строки с принятыми модельными решениями, 8 в карантине.
Оставшиеся 34 development-строки также исключены из supervised splits.
Binary label у принятых примеров сохранена; неопределённые метки не исправлялись
догадкой. Rationale/expected_behavior обновлены по журналу модельного ревью.
Manifest и review SHA256 пересчитаны; v1 и прежние benchmark-результаты не изменены.

Оставшиеся семейства различаются конкретной задачей/источником/эффектом, но
корпус по-прежнему синтетический, одного происхождения и сильно шаблонный.
Модельный просмотр не доказывает отсутствие всех семантических дублей. Test уже
наблюдался, 6 validation и 7 test семейств недостаточны для надёжных заявлений
о generalization или низкой FPR. Нужны новые независимые сценарии и замороженный
test; это отдельная задача расширения корпуса. Новых метрик качества v2 нет,
production-веса не заменялись.
