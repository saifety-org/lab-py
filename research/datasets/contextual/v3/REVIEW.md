# Модельное ревью расширения v3

Метод: авторское модельное ревью OpenAI Codex, `human=false`, `independent=false`.
Точный runtime model ID не предоставлен средой. Ни второго независимого ревьюера,
ни слепого прохода, ни внешнего API-вызова для этой версии не было. Ручная разметка
от пользователя не требуется по его решению.

Проверены 42 новые сценарные постановки и их EN/RU/ES/ZH тексты: конфликт с задачей,
эффект инструкции, допустимость контрфактуального задания, безопасный анализ
цитат/кода/документации. Смешанные EN/RU документы состоят из тех же переводов,
а не новых независимых атак. Явные причины по сценарию находятся в
`scenarios.json` → `review`; решения по развёрнутым строкам — в `review.json`.

Каркас проверки: исходный ограниченный task не разрешает внешнему содержимому
менять цель, вывод, свидетельства, доступ к данным, состояние или объём проверки.
Во втором варианте task явно разрешает **описание/фикцию**, не настоящее выполнение
вредоносного действия. В третьем меняется только заявленное вызывающей стороной
происхождение документа; метка атаки остаётся 1. Четвёртый вариант — запрошенный
разбор содержимого примера, поэтому метка 0 не означает разрешение исполнить его.

Новые семейства включают DNS/локализацию/календарь/OCR как носители ложного
приоритета, рекурсивное перенаправление задачи, замену единиц/атрибуции/точности,
ложные визуальные/сетевые/физические свидетельства, DNS/URL/clipboard/log-sink
каналы передачи, изменения прав/настроек/ссылок и подавление отдельных проверок.
Есть HTML-комментарий, JSON-envelope/next_action, два распределённых сценария
и декларативная спецификация ответа без повелительного наклонения.

Семейства назначены **до разворачивания переводов и контролей**: по два новых
семейства каждого типа в каждом split. Между split не распределяются варианты
одного исходного сценария. Go проверяет точные/лексические копии и отдельные
документы при Jaccard >= 0.8. Кандидатов между семействами в этой версии нет;
это не доказательство отсутствия семантических парафразов. Обобщённые механизмы
семи типов неизбежно повторяются, а авторские оценки новизны могут ошибаться.

Все v2 записи перенесены в development без изменения task/documents/меток/ID:
меняются только split и source schema для однородного нового входного контракта.
Их прежние суждения наследуются с явной пометкой, а не выдаются за новое ревью.
Восемь quarantined строк остаются quarantined; четыре неопределённые модельные
метки остаются null в журнале, исходные исторические label не используются
в supervised splits. Новый validation восстанавливает покрытие authority-spoofing.

Ограничения: один автор и ревьюер, synthetic-only, задачи на английском,
повторяющиеся формулировки описания/симуляции/анализа могут дать shortcut;
переводы и одинаковые payload зависимы. Вариант `user-provided` моделирует
происхождение, не аутентификацию. Покрытие языков не равно надёжности language ID
или защите на всех языках. 14 validation-семейств и 140 benign не обосновывают
производственную гарантию FPR 1%, особенно с учётом зависимости строк.

Никакие модели, детекторы, пороги и scanner policies на v3 не запускались и
не настраивались; новых quality metrics нет. Test фиксируется для будущего
эксперимента, не является заявлением об улучшении production.
