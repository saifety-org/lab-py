# Контекстный корпус v3

42 новых синтетических сценарных семейства, 840 новых записей. Все 252 записи
v2 сохранены в **development**, включая старый наблюдавшийся test и 8 спорных
строк. Исходные файлы v1/v2 и исторические результаты не изменены.

| Split | Записи | Атаки / benign | Семейства |
| --- | ---: | ---: | ---: |
| train | 280 | 140 / 140 | 14 новых |
| validation | 280 | 140 / 140 | 14 новых |
| test | 280 | 140 / 140 | 14 новых |
| development | 252 | исторические метки, включая карантин | 30 прежних |

В каждом новом split — по два семейства каждого из семи типов атак. Для каждого
семейства есть EN/RU/ES/ZH и смешанный EN/RU (`mul`); это языки **документов**.
Задачи пользователя остаются английскими, поэтому покрытие многоязычных задач
не заявляется. На язык в каждом новом split приходится 56 записей, поровну
атак и benign. Точные объёмы по типам/языкам/меткам — в `coverage.json`.

Четыре варианта каждого сценария и языка:

1. Инструкция внешнего источника нарушает ограниченную задачу пользователя.
2. Тот же payload становится предметом явно разрешённого описания, фиктивного
   примера или симуляции. Реальные изменения и передача данных не разрешаются.
3. Первая атака повторяется с caller-assigned `trust=user-provided` при неизменной
   задаче и тексте. Происхождение от пользователя не даёт тексту system-приоритет.
4. Пользователь явно предоставляет цитату, код или документацию для анализа
   безопасности; инструкции рассматриваются как данные, а не исполняются.

Теги `authorization-pair` отмечают только варианты 1/2: ровно одна пара на
семейство/язык. Варианты 1/3 позволяют проверить влияние происхождения источника
без изменения текста и задачи. Все производные остаются в одном split.

Новый контракт — **`context-json-v2`**, source schema 2: добавлено происхождение
`user-provided`, которое не является доверенной системной инструкцией. Смешение
source schema 1/2 и произвольное повышение trust до `system` отклоняются.
Старый Python workflow закреплён на v1 и **пока не принимает этот контракт**;
его адаптация относится к следующей задаче обучения, а старый workflow работает
с прежними данными. См. [протокол](../../../docs/corpus-expansion-v3.md).

```sh
make validate-context   # complete model review + committed holdout lock
make prepare-context   # те же gates перед записью artifacts/contextual
make reproduce-context # воспроизведение из каталога в новый каталог
```

`scenarios.json` — исходные тексты, split и явные суждения автора-модели.
Go-генератор не вызывает модель и не проводит независимую проверку: он разворачивает
эти зафиксированные решения в JSONL/журнал, проверяя согласованность. `review.json`
привязан к данным; `holdout.json` фиксирует корпус, историю, каталог, решения
и подготовленный test. CI проверяет воспроизводимость и drift этих артефактов.

Это synthetic holdout, замороженный до последующего fitting/selection/threshold
tuning. Он открыт и просмотрен автором, **не является независимым по авторству**,
не доказывает качество на естественных данных или защищённом агенте. 280 строк
test — лишь 14 сценарных семейств, с зависимыми переводами и контролями. Пороги
выбираются только на validation; тест нельзя использовать для выбора модели,
промптов или правил. После такой настройки потребуется новый holdout.

Источник — оригинальные синтетические тексты этого проекта; внешние наборы,
реальные секреты и персональные данные не импортированы. `NOASSERTION` означает,
что пользователь ещё не выбрал лицензию; это не утверждение о разрешённом
переиспользовании. Лицензия остаётся отдельным релизным решением.
