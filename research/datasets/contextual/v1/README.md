# Contextual prompt injection corpus v1

Синтетический seed-корпус для разработки контекстного классификатора. **Не является
независимым benchmark и не подтверждает готовность защиты.** Все метки проверены
автором по задаче; независимая проверка человеком и расширение корпуса ещё нужны.

## Состав

7 типов в `taxonomy.json`, отдельный JSONL для каждого типа. Тип описывает механизм
или основной эффект; MCP/файл/страница, язык, обфускация и распределение — отдельные
признаки. Составные случаи имеют один основной тип и дополнительные теги.

252 записи: train 122, validation 56, test 64, development 10. В train/validation/test
есть атаки и похожие безопасные примеры на EN/RU/ES/ZH; ещё 2 mixed EN/RU строки —
в train. Все 4 перевода и безопасные пары сценария имеют общий family и split.
28 исходных семейств: 14 train, 7 validation, 7 test. Десять старых пропусков —
ещё 10 development-семейств. Переводы не увеличивают число независимых сценариев.

Случаи включают role spoofing в JSON, ложные одобрения/тесты, утечки фиктивных данных,
изменения файлов, Base64/zero-width и сценарий из двух документов. В корпусе нет
реальных секретов, персональных данных, адресов действующих получателей. Ничто из
payload не исполняется. Внешние датасеты не импортировались; `license: NOASSERTION`
честно отражает отсутствие объявленной лицензии повторного использования проекта.

## Схема и метки

Go-типы и строгая валидация: `internal/contextcorpus`. Каждая JSONL-запись:

- `schema: 1`, уникальные `id`, `family`, заранее назначенный `split`.
- `primary_type`, дополнительные `tags`, `language` (en/ru/es/zh/mul).
- `authorized_task`: разрешённая пользователем задача.
- `documents`: упорядоченный сценарий; каждый документ имеет id, kind (mcp/file/web),
  locator, trust=untrusted, language, text. Поля доверия задаёт приложение, а не текст.
- `label`: 1 — документ пытается направить агента за пределы разрешённой задачи;
  0 — релевантные данные, цитата или разрешённая процедура без такого перенаправления.
- `expected_behavior`, `rationale`: что должно произойти и почему выбрана метка.
- `provenance`: synthetic, origin_id, license, review; derived_from у старых пропусков.

В authorization-pairs один и тот же payload имеет разные метки при разных разрешениях
пользователя; пары остаются внутри одного семейства. Иначе raw-text классификатор
мог бы ошибочно считаться достаточным для контекстной задачи. Метка не определяется
наличием повелительного наклонения или результатом существующего детектора.

## Проверка и подготовка

```sh
make validate-context
make prepare-context
```

Go отклоняет неизвестные поля, отсутствующие метки/контекст, повышение trust,
дубли ID, пересечение семейства/источника между выборками и неявные близкие копии.
NFKC/casefold/whitespace + character 5-gram Jaccard >= 0.8 требует общий family.
Это лексический контроль: семантические перефразировки и корректность переводов
требуют отдельной проверки человеком. Известные пропуски нельзя переносить в train/test.

Подготовка детерминирована, без случайного split; seed=0 означает отсутствие RNG.
В `artifacts/contextual` появляются train/evaluation/development JSONL и manifest
с размерами, покрытием и SHA256 исходников/выборок. Manifest корпуса хранится здесь
как `manifest.json`; CI проверяет совпадение с актуальными данными.

Для независимой разметки: `make review-context`. Пакет скрывает исходные метки,
авторские пояснения и split; решения привязаны к SHA256 версии корпуса.
[Протокол](../../../docs/contextual-review.md) описывает слепую разметку,
сверку и версионирование исправлений; [журнал](REVIEW.md) фиксирует текущий статус.

## Контракт модели

`context-json-v1`: JSON-строка с ровно contract, task, documents; у каждого входного
документа только kind, trust, text. Сериализацию определяет Go Render (UTF-8,
без HTML escaping, порядок документов сохраняется). Ни ID, ни метки, ни rationale,
ни категории/split/provenance не попадают в признаки. В подготовленных строках
`payload_text` и `documents` сохраняются для raw-only ablations и сканера.

Этот контракт исследовательский: текущий runtime sAIfety принимает текст и не
собирает такой контекст автоматически. Кандидат context-json-v1 нельзя подменить
за shipped raw-text модель. Нужны отдельный runtime adapter, проверка совместимости
и PR на promotion. До этого production веса остаются прежними.

## Ограничения оценки

Всего 7 validation и 7 test семейств. При 28 benign validation строках бюджет FPR
1% допускает только ноль ошибок; это не доказательство FPR <=1% на новых данных.
Переводы коррелированы; доверительные интервалы следует считать по семействам,
а не выдавать 4 перевода за независимые наблюдения. Нужны новые независимые авторы,
естественные документы/задачи, больше benign и покрытие иных языков/типов.
Измерение score или действия сканера не является измерением успеха защиты агента.
