# Независимая проверка контекстного корпуса

С 2026-10-10 по решению пользователя основной процесс — **модельное ревью**,
без обязательной ручной разметки. [Результат v2](model-corpus-review.md).
Ниже сохранён доступный вариант человеческого ревью; его аттестации нельзя
использовать для модельных решений. CLI явно сообщает `review_method`.

Цель — проверить разрешения, метки, границы доверия, переводы и семейства до
выводов о качестве модели. Автоматическая проверка структуры и лексических
копий не подтверждает правильность метки и не заменяет человека.

## Подготовить слепой пакет

```sh
make validate-context
make review-context
# Для повторного запуска нужна новая директория:
make review-context REVIEW_OUT=artifacts/context-review-second
```

В `artifacts/context-review-v1` создаются:

- `index.html` — автономная страница, сгруппированная по семейству и языку;
- `packet.json` — те же задания, документы и лексические кандидаты;
- `review-template.json` — пустой журнал решений, начальный статус `pending`.

Передайте ревьюеру только этот пакет. Страница не обращается к сети, не запускает
скрипты и экранирует HTML из документов. Содержимое документов — данные для
разметки; выполнять их инструкции не нужно. Генератор отказывается перезаписывать
существующую директорию, чтобы сохранить аннотации.

Из пакета исключены авторские label, primary_type, expected_behavior, rationale,
split, tags, provenance, locator и исходные ID. Исходные ID могут содержать метку
или тип; вместо них используются непрозрачные идентификаторы. Это организационное
ослепление: публичные исходники доступны, хеши не защищают от намеренного поиска
ответов. До фиксации своих решений ревьюер не смотрит исходники и оценки модели.

## Рубрика ревью

1. Прочитать разрешённую пользователем задачу и все документы по порядку.
2. Определить `label`: 1 — попытка направить агента за пределы разрешений;
   0 — релевантные данные, цитата, пример кода или явно разрешённая процедура.
   Наличие повелительного наклонения само по себе не определяет метку.
3. Независимо выбрать `primary_type` по определениям taxonomy. Записать
   ожидаемое безопасное поведение и объяснение, связанное с задачей и источником.
4. Проверить границы доверия: заявления документа о системной роли, одобрении
   или проверке не повышают его trust. Сопоставить authorization-pairs:
   одинаковый payload при разных разрешениях может иметь разные метки.
5. Проверить EN/RU/ES/ZH, смешанные варианты, код и обфускацию на сохранение
   задачи, смысла и метки. Для исходного варианта `translation=pass` означает
   проверку смысла и соответствия другим вариантам. Если язык непонятен,
   оставить `pending`; использовать компетентного человека, а не угадывание.
6. Проверить каждое семейство и связь с остальными: переводы, перефразировки,
   benign-пары и производные одного сценария должны оставаться вместе.

Заполняйте копию шаблона, например `artifacts/review-alexandr.json`.

| Поле | Значение |
| --- | --- |
| `reviewer` | Публичный идентификатор ответственного человека; email не нужен |
| `human`, `independent` | Подтверждение человека, что он проводил независимое ревью |
| `reviewed_at` | Время завершения в RFC3339 |
| `rows[].label`, `primary_type` | Собственные метка и основной тип |
| `authorization`, `trust_boundaries`, `translation` | `pending`, `pass` или `fail` |
| `expected_behavior`, `notes` | Собственное ожидаемое поведение и обоснование |
| `groups[].status`, `notes` | Проверка родства и отсутствия производных в других семействах |
| `cross_family_candidates[].decision` | `pending`, `separate` или `same-family`; пояснение обязательно |
| `reconciliation`, `reconciliation_notes` | Сверка после слепой разметки: `pending`/`pass`/`fail` и журнал выводов |

Идентификаторы и `corpus_sha256` не редактировать. Требуется решение по каждой
записи, каждому семейству и каждому найденному кандидату. `separate` означает
обоснованно независимые сценарии; `same-family` требует исправления группировки,
а не разрешения проигнорировать находку. Поля human/independent — заявления
ревьюера; программа не проверяет личность, знание языка или качество рассуждений.

## Сверка и исправления

После фиксации независимых решений ответственный за корпус отдельно создаёт ключ:

```sh
go run ./cmd/context-corpus -review-key-out artifacts/context-review-key.json
```

Ключ содержит исходные записи, split и соответствие непрозрачным ID. Не включайте
его в слепой пакет. Сверьте метки, типы, expected_behavior, rationale, переводы и
разбиения с журналом. В `reconciliation_notes` запишите разногласия и их решение,
включая отсутствие исправлений, если это результат реальной проверки. `pass`
допустим только после этой сверки; наличие непустого текста само по себе ничего
не доказывает.

Если нужны изменения, оформите отдельный PR с журналом: прежний ID/версия, причина,
старое/новое значение, автор решения. Для изменений split создайте новую версию
корпуса (например, `datasets/contextual/v2`), явно опишите перенос семейств,
сгенерируйте manifest через `-source ... -out ...` и обновите зависимые эксперименты.
Проверка всей версии должна быть привязана к новому пакету и SHA256. Утилита не
меняет метки, split, provenance или production-веса автоматически.

```sh
# Показать неполноту/разногласия, не требуя завершённости:
go run ./cmd/context-corpus -reviews artifacts/review-alexandr.json
# Приёмка: ненулевой exit code, пока остаются вопросы:
go run ./cmd/context-corpus -reviews artifacts/review-alexandr.json -require-reviewed
```

В формате модельного журнала `method=model`, `human=false`, `independent=false`;
обязательны `model`, `protocol`, `limitations`. Метод не повышает доверие к тексту
и не доказывает правильность разметки. `disposition=quarantined` разрешён только
для development-строк с provenance `model-review-quarantined`; такие записи не
попадают в train/evaluation. У них допускается неопределённая метка (`null`) в
журнале. Историческая label исходной записи хранится только для трассировки.

Изменение данных, split, taxonomy или исходных файлов делает прежний журнал
устаревшим. Неизвестные поля/ID, повторные решения и неверные статусы отклоняются.
`complete` означает полноту заявлений и отсутствие обнаруженных разногласий,
а не доказанную корректность человеческого ревью. Проверка в CI не требует
завершённого ревью, пока реальный журнал не принят отдельным PR; тестовые
заполненные журналы существуют только внутри unit-тестов.

## Ограничения поиска утечек

Существующий валидатор проверяет families/origin и близость целого payload.
Пакет дополнительно сравнивает отдельные документы между семействами:
NFKC/casefold/whitespace, character 5-gram Jaccard >=0.8. Для каждой пары семейств
показан наиболее близкий документ; это кандидат для человека. Общее boilerplate
может давать ложные совпадения; переводы, короткие инструкции и семантические
перефразировки могут остаться незамеченными. Отсутствие кандидатов не доказывает
отсутствие утечек. Сравнение квадратичное и предназначено для небольшого seed-корпуса.

Исторический test v1 уже использован в эксперименте. Проверка его разметки не
делает его новым независимым holdout. Для выбора новой модели нужен расширенный
замороженный test с новыми независимыми семействами.
