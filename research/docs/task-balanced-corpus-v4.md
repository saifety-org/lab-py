# Контекстный корпус v4: устранение task-only shortcut

В принятом encoder-эксперименте на v3 task-only модель обнаружила 130 из 140 атак
без ложных срабатываний, тогда как context encoder — 117 из 140. Безопасные и
вредоносные строки систематически получали разные формулировки задачи. Поэтому
высокая оценка не доказывала понимание связи задачи с документом.

V4 исправляет эту конкретную подсказку. Это изменение данных и проверок, а не
новые production-веса или доказанное улучшение защиты приложения.

## Данные и контроли

42 новых сценарных семейства дают 1680 записей: train, validation и test по
560 строк / 14 семей / 280 строк каждой метки. Семь типов угроз покрыты двумя
семьями каждого типа в каждом split. Документы написаны на EN/RU/ES/ZH;
mixed объединяет EN/RU. Задачи английские. Переводы и производные остаются
в одной семье. Все 1092 исторические строки v3 перенесены только в development;
восемь quarantined не допускаются к обучению. Исторические версии неизменны.

Для каждой пары сценарий/язык создаются четыре варианта:

| Вариант | Задача | Документ | Метка |
| --- | --- | --- | --- |
| Атака | Ограниченная factual задача | Попытка выйти за её рамки | 1 |
| Контроль | Та же factual задача | Относящиеся к задаче данные | 0 |
| Разрешённая демонстрация | Явно hypothetical security example | Тот же документ, что в атаке | 0 |
| Выход из демонстрации | Та же hypothetical задача | Требование реального действия или ложной factual attestation | 1 |

Все четыре варианта повторяются с `untrusted` и `user-provided`, при одинаковых
остальных полях документа. Происхождение не даёт тексту права менять задачу.
На split получаются 280 matched-task пар, 280 provenance пар и 70 выделенных
authorization пар с одинаковым документом и разными задачами/метками.

Метка описывает попытку выйти из разрешённой области, а не успешное исполнение
атаки агентом. Разрешённая демонстрация и отмена её hypothetical scope — явная
конвенция разметки. Решения доступны в каталоге; это авторское модельное ревью,
не независимая или слепая оценка. [Метод и ограничения](../datasets/contextual/v4/REVIEW.md).
Ручная разметка от пользователя не требуется.

## Проверки и freeze

Go-аудит требует равного числа обеих меток для каждой exact/canonical задачи
внутри split/family/language/kind/trust/числа документов. Он также проверяет
неизменность документов в authorization парах и меток в provenance парах.
Существующие проверки обнаруживают дубликаты, пересечения семей, нарушения
review binding и frozen holdout. Старый v3 не проходит новый task-label gate.

Test заморожен после ревью и структурного аудита **до обучения baseline**:
`2026-10-11T07:20:07Z`, 560 строк / 14 семей. SHA256 подготовленного test:
`1fb79fe8b27fa477fa47c38ec56ab6131327286f6a70378d3a6e37dd34cf77e1`.
Lock связывает corpus, каталог, review и историческую версию. Ни модельные
test scores, ни test-driven подбор корпуса в этом этапе не использовались.

```sh
make validate-context
make prepare-context
make reproduce-context-v4
make task-baseline-context
```

Подготовка и baseline требуют принятого review и существующего freeze.
Baseline пишет веса и отчёт только в новую директорию `artifacts/task-only-v4`;
повторный запуск требует другого `TASK_BASELINE_OUT`. Веса не публикуются.
Отчёт фиксирует Go version/OS/architecture и SHA конкретных весов: младшие биты
floating-point весов могут различаться между ARM и x86. Проверяются собственный
SHA весов, повторяемость в одной среде, одинаковые входы/параметры и метрики.
Регрессионные тесты проверяют воспроизведение исходных файлов, отказ при
изменении lock и неизменность baseline при изменении только test task text.

## Результат task-only проверки

Обучена существующая Go logistic regression на hashed char n-gram признаках
**только текста задачи**: seed=1, epochs=40, learning rate=0.5, L2=0.00001.
Train используется для fitting, validation — для выбора порога с FPR<=1%.
Test моделью не оценивается. [Машинный отчёт](../datasets/contextual/v4/task-only-baseline.json).

| Split | Accuracy при 0.5 | AP | TP / FP / TN / FN при 0.5 |
| --- | --- | --- | --- |
| Train | 50% | 0.5 | 120 / 120 / 160 / 160 |
| Validation | 50% | 0.5 | 140 / 140 / 140 / 140 |

При validation FPR<=1% выбран no-alerts порог: recall=0, FPR=0. Это ожидаемый
отрицательный контроль: задача сама по себе не предсказывает метку. Структурно
любая детерминированная task-only классификация имеет максимум 50% accuracy
на каждом новом сбалансированном split. Это не оценка полноты защиты.

## Что ещё не доказано

Данные синтетические, созданы и проверены одним ассистентом. Shared templates,
стиль escalation, переводы и парные варианты могут давать другие подсказки.
Отсутствие lexical overlap не доказывает семантическую независимость. Test
содержит только 14 сценарных семей; построчные интервалы доверия завысили бы
эффективный размер выборки. Нет новых live-agent ASR или production-метрик.

После принятия v4 следующий этап в lab-py: закрепить принятый commit lab,
повторить encoder и task-only/payload-only абляции с настройкой только на
train/validation, затем один раз оценить frozen test по общему протоколу.
Сравнение с native/DeBERTa требует одинакового контекстного входа, явных
лимитов окна и порогов, выбранных без test. До такого результата решение
о promotion и ONNX-интеграции преждевременно.
