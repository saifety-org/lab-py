# Расширение корпуса и замороженный test

Цель v3 — отдельные новые сценарные семейства для train/validation/test,
контрфактуальные задачи и benign-примеры, а не увеличение независимой выборки
за счёт переводов. Данные, каталог и генератор находятся в lab. Core, веса модели
и закреплённые версии прежних экспериментов не меняются.

## Входной контракт

`context-json-v2` сохраняет поля `contract/task/documents(kind,trust,text)`.
Source schema 2 допускает `trust=untrusted|user-provided`; второе означает
происхождение, назначенное вызывающей стороной, а не приоритет или разрешение
выполнить содержащуюся инструкцию. Текст документа не может назначить себе trust.
Нет состояния `system`, `developer` или автоматически доверенного MCP-ответа.
Отсутствующее runtime-свидетельство происхождения нельзя подменять `user-provided`.

Source schema 1 продолжает рендериться в `context-json-v1` и допускает только
`untrusted`; старые manifest и модельные входы воспроизводятся без изменений.
Один корпус не может смешивать source schemas. Labels/ID/type/rationale/language/
review/split/provenance по-прежнему не попадают в модельный вход.

Lab-py сейчас принимает только старый контракт. Следующий encoder PR должен
явно добавить новый контракт и enum trust, закрепить принятый commit lab и
проверять `holdout.json` перед подготовкой/обучением/оценкой. Само наличие lock
в lab **не заставляет внешнего потребителя соблюдать его**. До этой адаптации
нельзя передавать v3 в старые команды или молча удалять trust/менять contract.

## Воспроизведение и приёмка

```sh
make validate-context
make prepare-context
make reproduce-context
```

`cmd/context-expand` читает декларативный `scenarios.json` и принятую v2 с её
журналом. Проверяет явные авторские решения, языки и границы документов,
переносит прежние строки в development, разворачивает четыре варианта,
проверяет межсемейные лексические кандидаты и привязывает журнал к новым данным.
Существующий output не перезаписывается. Каталог — сохраняемая основа текстов
и решений; программное разворачивание решений не считается независимым ревью.

`coverage.json` содержит количество строк по split/type/document-language/label
и количество семейств по split/type. Нельзя считать переводы и контрфактуальные
варианты независимыми наблюдениями. Для будущих интервалов bootstrap единица
выборки — семейство; отчёты по языкам должны раскрывать повторное происхождение.

## Заморозка test

`holdout.json` (`context-holdout-v1`) фиксирует SHA256 всего корпуса, исходного
каталога, исторической v2, нормализованного журнала ревью и **точных JSONL-байтов
подготовленного test**, отдельно от evaluation-файла с validation+test.
Фиксируются также дата, количество test-строк/семейств и политика использования.
Это защита от незаметного drift, не криптографическое доказательство того,
что автор не видел test или что экспериментатор его не использовал.

Обычная подготовка через Make сначала проверяет complete review и lock; при
ошибке выходные данные не записываются. Создание lock — отдельная явная операция:

```sh
go run ./cmd/context-corpus -source <new-version> \
  -reviews <new-version>/review.json -history datasets/contextual/v2 \
  -catalog <new-version>/scenarios.json -freeze-out <new-version>/holdout.json
```

`-freeze-out` отказывается перезаписывать файл. **Не пересоздавать принятый v3
lock ради прохождения CI.** Исправление test/разметки/группировки требует новой
версии, нового ревью и явного объяснения в PR. Изменение только формата JSON
каталога также меняет его SHA; журнал нормализуется перед хешированием.

Test заморожен до последующего fitting/selection/threshold tuning. Автор его
видел; независимость от обучающих сценарных семейства не означает независимое
авторство, отсутствие общих шаблонов или естественное распределение угроз.
Модель/правила/threshold выбираются только по train/validation с заранее
объявленным бюджетом. Если test использован для выбора или исправления
детектора, он становится историческим и потребуется следующий test.

При сравнении с DeBERTa и native соблюдать одинаковые строки и разделения,
validation-only пороги, отдельные входные постановки и task/payload абляции.
V3 сам по себе не является новым результатом сравнения, заменой весов,
оценкой attack success rate защищённого агента или релизной приёмкой.
